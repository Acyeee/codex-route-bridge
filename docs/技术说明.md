# 技术说明

面向想了解原理、或把线路引擎接入自己界面的开发者。普通使用请看 [README](../README.md)。

## 工作原理

```
Codex 桌面版 ──(CODEX_CLI_PATH)──> codex-route-bridge.exe ──> 官方 codex app-server
                                       │
                                       ├─ account/read 等请求：原样转发（继续用 ChatGPT 登录）
                                       ├─ thread/start · resume · fork：改用第三方 API 提供方
                                       ├─ model/list：换成第三方 API 的模型列表
                                       └─ thread/start · turn/start 的 model：第三方 API 有就照用，没有就用默认模型
```

1. `src/engine/desktop-helper.py` 是线路引擎：管理线路、加密保存密钥、检测连接、拉取模型列表、启动 Codex。
2. `src/engine/Start-ManagedCodex.ps1` 找到已安装的官方 Codex（Microsoft Store 版），按需安全地关闭正在运行的实例，然后带着线路参数重新启动它。
3. 启动时 Codex 的 `CODEX_CLI_PATH` 指向 `codex-route-bridge.exe`（源码在 `src/bridge/ManagedRoute.cs`）。桥接程序启动真正的官方 CLI，并只改写线程类请求的 `modelProvider` 与 `model`。
4. 桥接程序在第一个线程请求被第三方 API 线路接受后写入 `desktop-confirmation.json`，界面据此显示“已生效”。
5. 选第三方 API 线路时，Codex 从一份**本机兼容副本**启动：`src/engine/compat/` 会把官方 Codex 复制到 `%USERPROFILE%\.codex\route-switch\compat\<版本号>\`，对副本做兼容调整，让它在第三方 API 线路下不受官方账号额度状态的影响（额度提示、输入限制等）。官方安装目录不会被修改；副本每次生成都会校验完整性。Codex 更新后会自动为新版本重新生成；遇到无法适配的版本，则退回直接启动官方程序。

## 环境要求

- Windows 10/11
- Microsoft Store 版 Codex 桌面应用（包名 `OpenAI.Codex`）
- Python 3.10 及以上
- .NET Framework 4.x（Windows 自带，用于编译桥接程序，无需另装）
- Node.js（生成兼容副本时用来做语法校验）
- 每个 Codex 版本的兼容副本约占 2.3GB 磁盘空间

## 命令行接口

`codex-route.cmd` 首次运行时会自动编译桥接程序，也可以手动编译：

```powershell
.\src\build.ps1
```

会在 `src\engine\` 下生成 `codex-route-bridge.exe`。仓库不包含任何预编译的二进制文件。

线路引擎通过标准输入接收一条 JSON 请求，再从标准输出返回一条 JSON 结果，便于接入任何图形界面（例如在 [Metera](https://github.com/Sutera-Diffusus/metera) 这类桌面应用里加一个线路管理页）：

```powershell
'{"operation":"list"}' | python -I src\engine\desktop-helper.py
```

成功时返回 `{"result": ...}`，失败时返回 `{"error": "可读的原因"}`。

| 操作 | 参数 | 说明 |
|---|---|---|
| `list` | — | 列出线路、当前选中线路、正在运行的线路 |
| `save` | `id` `name` `baseUrl` `model` `models` `key` | 新增或修改第三方 API 线路。`models` 是可选的模型列表（通常就是 `models` 操作拉到的结果），全部会出现在 Codex 的模型选择器里；`model` 是新任务的默认模型。编辑时 `key` 可留空以保留原密钥 |
| `models` | `baseUrl` `key`，或已保存线路的 `id` | 从 `<baseUrl>/models` 拉取模型列表 |
| `check` | `id` | 检测连接并确认所选模型存在，不发起模型调用 |
| `select` | `id` | 设为当前线路（下次启动生效） |
| `remove` | `id` | 删除第三方 API 线路，密钥文件改名为 `.dpapi.removed` |
| `launch` | `id` `restart` `allowForce` | 以该线路启动 Codex；`restart` 允许替换正在运行的实例 |

示例：添加一条线路并启动

```powershell
'{"operation":"save","args":{"id":"my-api","name":"我的第三方 API","baseUrl":"https://api.example.com/v1","model":"gpt-5.5","key":"sk-..."}}' | python -I src\engine\desktop-helper.py
'{"operation":"launch","args":{"id":"my-api","restart":true}}' | python -I src\engine\desktop-helper.py
```

也可以直接运行 `src\engine\Start-Codex.ps1 -Restart`，按当前选中的线路启动。

## 本地状态

默认保存在 `%USERPROFILE%\.codex\route-switch\`，可用环境变量 `CODEX_ROUTE_HOME` 改到别处：

| 文件 | 内容 |
|---|---|
| `profiles.json` | 线路列表（不含密钥） |
| `active-profile.json` | 当前选中的线路 |
| `credentials\<id>.dpapi` | DPAPI 加密的 API Key，只有同一 Windows 账户能解密 |
| `desktop-launch.json` / `desktop-confirmation.json` | 最近一次启动和生效确认 |
| `compat\<版本号>\` | 第三方 API 线路使用的 Codex 兼容副本及校验记录 `verification.json` |

## 安全设计

- 远程地址必须是 HTTPS；只有本机地址允许 HTTP。地址里不能带账号、密码或查询参数。
- 密钥只在进程内使用：不进日志、不进返回结果；启动失败时，报错中的密钥会被替换为 `***`。
- 关闭 Codex 时先请求窗口正常关闭，超时后才在得到允许的情况下结束**同一路径、同一启动时间**的进程树，不会误杀其他程序。
- 不修改 Codex 的安装目录；兼容调整只作用于本机副本。

## 已知限制

- 兼容副本按 Codex 版本生成。个别 Codex 更新可能让自动适配失效，这时会退回直接启动官方程序：第三方 API 线路仍可使用，但 Plus 额度用完后可能暂时发不出消息，需要等本项目更新适配。
- 只支持 Microsoft Store 版 Codex 桌面应用。
- 第三方 API 需要兼容 OpenAI Responses API（`wire_api = "responses"`）。
- Codex 更新后如果改了桌面端与 CLI 的通信方式，桥接程序可能需要跟着调整。
